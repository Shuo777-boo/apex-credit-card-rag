# 系统架构

## 数据与构建

官方语料与评测题统一保存在 `data/`。导入时验证150个唯一文档和30道评测题，记录数据摘要、原文、卡种、分类和年份。评测标签与参考回答仅用于评估，不参与向量生成或检索。

`ingestion` 支持固定滑动窗口与政策层级分块，保留父文档和字符偏移。每个构建绑定数据摘要、分块参数、模型及向量维度，使用嵌入缓存复用未变化内容。完成数据和 HNSW / GIN 索引检查后切换活动构建。

SQL 迁移统一位于 `backend/src/apex_rag/storage/migrations/`，同时用于源码安装和 wheel 安装。

## 检索与回答

1. Query Embedding：`text-embedding-v4`，默认1024维。
2. Dense：pgvector 余弦相似度检索。
3. Sparse：PostgreSQL 英文 `tsvector` / `ts_rank_cd` 全文检索。
4. Fusion：RRF 按排名融合，两路采用相同卡种过滤。
5. Rerank：`qwen3-rerank` 重排候选集，按原始文档去重返回 Top-K。
6. Answer：`qwen3.5-plus` 依据当前证据生成回答，引用关联至原文。

多轮对话最多使用三个完整历史问答轮改写独立检索问题。历史回答不能作为政策证据；实际检索问题与阶段耗时随结果返回。

`retrieval_total` 包含在线向量化与重排；数据库延迟只包含数据库检索阶段。引用ID和原文匹配校验不能证明语义正确。

## API 与界面

FastAPI 提供 `/api/v1/search`、`/api/v1/answer`、文档读取、评测任务与报告接口，Pydantic 模型定义见 `schemas/`。完整接口定义以运行中的 `/openapi.json` 为准，Swagger 位于 `/docs`。

React 工作台展示回答、引用、原文与检索过程。评测页支持单配置和六组对比，创建任务前核对配置、费用及预算。任务状态保存在 PostgreSQL，使用单进程执行器、并发上限1；服务重启不自动恢复付费执行。

统一错误响应包含 `request_id` 和 `error`。模型请求采用有限重试与超时，校验失败明确报错。就绪检查验证数据、构建与索引完整性，不调用模型。

## 扩展与边界

Iceberg 管理版本化向量快照，通过有效快照执行精确扫描。GraphRAG 从来源政策建立有限跳图关联，将新增候选送入同一核心重排。LLM Judge 单独衡量上下文相关性和回答忠实度，原始结果、失败及恢复阶段均保留。

当前应用为开发演示，企业身份、文档级授权、PII处理和大规模容量方案见 [roadmap.md](roadmap.md)。
